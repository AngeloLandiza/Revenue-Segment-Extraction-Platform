# Exports

Final export is available only after document approval. The export service writes files to:

```text
exports/{document_id}/
```

Generated files:

- `revenue_segments.csv`
- `revenue_segments.xlsx`
- `audit_export.json`

## Review Gate

`ExportService.export_document(document_id)` blocks unless:

- the document status is `approved`
- every segment row is `approved`, `edited`, or `rejected`

Rejected rows are excluded from the main CSV/XLSX output by default. They remain in the audit JSON with their evidence and review events.

## CSV and XLSX Columns

The CSV and XLSX files use this stable column order:

1. `company_name`
2. `document_name`
3. `fiscal_period`
4. `segment_name`
5. `revenue_value`
6. `revenue_raw`
7. `currency`
8. `scale`
9. `revenue_unit`
10. `normalized_value`
11. `period_label`
12. `page_ref`
13. `section_ref`
14. `evidence_text`
15. `metric_basis`
16. `confidence`
17. `review_status`
18. `reviewer_note`
19. `nace_code`
20. `nace_label`
21. `nace_level`
22. `nace_rank`
23. `nace_match_score`
24. `nace_rationale`
25. `nace_confidence`
26. `esg_factor_summary`
27. `scoring_model_label`
28. `base_score`
29. `esg_adjustment_score`
30. `segment_score`
31. `weight_share`
32. `score_rationale`
33. `company_score`

NACE fields are populated from the reviewer-selected NACE mapping when one exists. If there is no explicit selection but candidates were generated, the top candidate is exported. `nace_confidence` is retained for backwards compatibility and currently mirrors `nace_match_score`.

`esg_factor_summary` includes only segment-linked ESG factors whose review status is `approved` or `edited`. Company-wide ESG factors, rejected ESG factors, and pending ESG factors are not copied into segment summaries.

Scoring fields are generated by `ScoringService` during export so they reflect the current reviewed rows and scoring config. They are labeled as prototype/demo only and are not official ratings or sustainability scores. Rejected rows are excluded from scoring. Unreviewed rows cannot reach final export because of the review gate.

## JSON Audit Export

`audit_export.json` includes:

- document metadata
- all segment rows, including rejected rows
- segment evidence and flattened evidence
- NACE candidates and selected/overridden NACE mapping per segment row
- ESG factors linked to each segment row
- segment score records linked to each segment row
- company-level prototype score summary
- all ESG factor records with event-derived review status and export-inclusion flags
- validation issues and validation issue review state
- review events
- export timestamp
- pipeline version and config summary

Reviewed values are stored in each row's `current_values`. Original extracted values are preserved where review events captured field-level `old_value` and `new_value` changes.

ESG audit records include `review_status`, `included_in_main_export_summary`, and `excluded_reason`. The JSON audit export keeps company-wide and rejected ESG factors for traceability even when they are not included in the main CSV/XLSX segment summary.

Score audit records include the stored `SegmentScore` fields and JSON rationale. The company score object includes weighted average, included revenue share, denominator, scale bounds, score direction, and calculation rationale.

## Streamlit Workflow

In the Streamlit app:

1. Review or edit each segment row.
2. Approve valid rows and reject unusable rows.
3. Resolve blocking validation issues or acknowledge reconciliation mismatches with a note.
4. Review ESG factors in the `ESG Factors` tab. Edit, unlink, relink, approve, or reject factors as needed.
5. Open the `Scoring` tab and click `Compute prototype scores` to preview reviewed-row scoring.
6. Approve the document.
7. Use the `Create export files` button in the Export section.

The UI shows the latest export path and timestamp from persisted `ExportRecord` rows.

## Evaluation Inputs

The evaluation CLI can consume final export artifacts without changing the export contract:

```bash
.venv/bin/python -m revenue_segment_extractor.evaluate --gold 'data/gold/*.csv' --pred exports
```

When an export directory contains both `audit_export.json` and `revenue_segments.csv`, the evaluator uses `audit_export.json` because it includes validation issues, review events, selected NACE mappings, and timestamps. If only `revenue_segments.csv` is available, row matching, value accuracy, page accuracy, and reviewer edit rate still work, but reconciliation and timing metrics may be unavailable.

Evaluation reports are written to:

- `reports/evaluation_summary.md`
- `reports/evaluation_results.csv`
- `reports/failure_analysis.md`
